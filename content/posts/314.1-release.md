We are pleased to announce the Pyodide 314.1 release.

This release focuses on more reliable stack switching and a faster Python <-> JavaScript FFI.

For the full list of changes, see the
[changelog](https://pyodide.org/en/stable/project/changelog.html#version-314-1-0).

## Stack Switching Improvements

Stack switching (based on [JSPI](https://github.com/WebAssembly/js-promise-integration))
lets synchronous Python code wait for JavaScript promises through
[`run_sync()`](https://pyodide.org/en/stable/usage/api/python-api/ffi.html#pyodide.ffi.run_sync)
and `callPromising()`. Since 314.0 we fixed several bugs in how Pyodide
manages the Python thread state when a stack is suspended and resumed.

### `contextvars` and `threading.local()`

Before, `contextvars` and `threading.local()` values could be lost or leak
between calls when code used `run_sync()`. For example, top-level code could
lose its context when suspended stacks resumed in a different order than they
were suspended in, and a `ContextVar` set inside one suspended call could show
up in an unrelated call later.

Now they behave the way you would expect from native Python:

- `contextvars` are propagated into the call, and each call that stack
  switches runs in a copy of the context. A `ContextVar.set()` inside the call
  does not leak out to the caller.
- `threading.local()` is shared between the caller and the call. Pyodide only
  has one thread, so changes made inside the call are visible outside, exactly
  as they would be in a single-threaded native program.

This matters most for web frameworks that keep per-request state in
`contextvars` or thread locals, such as Django, Flask, and Streamlit.

## Package Loading Improvements

### Package installer in JavaScript

The package installer used by `pyodide.loadPackage()` has been rewritten in
TypeScript ([#6354](https://github.com/pyodide/pyodide/pull/6354)). Before,
wheels were extracted by Python's `shutil` / `zipfile` running inside
WebAssembly. Now they are extracted in JavaScript with
[fflate](https://github.com/101arrowz/fflate) and written directly to the
Emscripten file system.

exact speedup depends on the size and contents of the wheel.

Since the installer no longer needs the Python interpreter, packages can be
installed before the interpreter finishes starting up.

### Loading shared libraries on demand

Pyodide used to load every shared library (`.so` file) in a package as soon as
the package was installed with `micropip.install()` or `pyodide.loadPackage()`.
This was a workaround for a browser restriction: on the main thread, Chrome only
allowed compiling WebAssembly modules smaller than 4KiB synchronously, so
`dlopen()` could not compile a library on demand. Every library had to be
compiled asynchronously ahead of time.

This restriction has been relaxed. Firefox and Safari no longer have such a
limit, and Chromium-based browsers (Chrome, Edge) raised it to 8MiB.
This is large enough for the shared libraries in most Python packages.

So starting with this release, `loadPackage()` no longer preloads shared
libraries smaller than 8MiB. They are loaded by `dlopen()` when they are first
needed, typically when you `import` the module. As a result:

- Installing packages is faster, especially packages that ship many extension
  modules that you never import.
- Memory usage goes down, since unused libraries are never loaded.
- The first `import` of a module with extension modules can take a little
  longer, because the library is compiled at that point.

If you want the old behavior, set the `sharedLibraryPreloadThreshold` option
of `loadPyodide()`:

```js
const pyodide = await loadPyodide({ sharedLibraryPreloadThreshold: 0 });
```

## Performance Improvements

We spent a lot of time on the performance of the Pyodide FFI in this release.
Compared to 314.0.0, common operations are significantly faster:

| Operation | Speedup vs 314.0 |
| --- | --- |
| `toJs()` on lists of int / float / str | 3.5–7.5× |
| `toJs()` on nested containers | 7× |
| `toJs()` / `toPy()` on a list of records | 2× |
| Python `str` → JS string (64 chars – 64 KiB) | 3.5–180× |
| JS string → Python `str` | 1.5–4× |
| Attribute get / set on a `JsProxy` (from Python) | 2.4–3.5× |
| Attribute get on a `PyProxy` (from JavaScript) | 2.9× |
| Function / method calls across the FFI | 1.5–2× |

## Package Changes

As announced in the 314.0 release, now that packages can publish PyEmscripten
wheels to PyPI ([PEP 783](https://peps.python.org/pep-0783/)), we are
gradually reducing the number of packages that Pyodide builds and tests itself.

The following packages have been removed from the Pyodide distribution because
they now publish PyEmscripten wheels on PyPI. You can still install them with
`micropip.install()`:

- apsw
- awkward-cpp
- blosc2
- fastcan
- gsw
- python-flint
- RobotRaconteur

We will keep removing packages that are available on PyPI. If your project
relies on a package being part of the Pyodide distribution, we recommend
switching to `micropip.install()`, or using a custom lockfile.

If you maintain a package with C, C++, or Rust extensions, consider publishing
PyEmscripten wheels to PyPI. See
[our guide](https://pyodide.org/en/stable/development/building-packages.html)
for how to build them, or open an issue in
[pyodide-build](https://github.com/pyodide/pyodide-build) if you need help.
